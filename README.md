## О проекте

В рамках курсовой работы разработан веб-сервис для прогнозирования вероятности дефолта по кредитным картам

### Используемые данные

Датасет UCI Credit Card содержит информацию о 30тыс клиентах:
- Демографические данные (возраст, пол, образование, семейное положение)
- Лимит кредита
- История платежей за последние 6 месяцев
- Суммы выписок и платежей

Целевая переменная - факт дефолта в следующем месяце

## Модели

### v1 -RandomForestClassifier

Классический ансамблевый метод. Хорошо работает на табличных данных, устойчив к переобучению.

- n_estimators: 100
- Точность на тесте: ~0.82

### v2 -GradientBoostingClassifier

Бустинговая модель последовательно исправляет ошибки предыдущих деревьев. Обычно дает более точные результаты, но требует больше времени на обучение.

- n_estimators: 100
- learning_rate: 0.1
- max_depth: 5
- Точность на тесте: ~0.82

Обе модели показывают примерно одинаковую общую точность, но различаются в деталях -поэтому есть смысл сравнивать их на реальных данных через A/B тест.

## Архитектура решения

### Почему монолит?

Для учебного проекта выбран монолитный подход:
- Один контейнер проще развернуть и поддерживать
- Нет накладных расходов на сетевое взаимодействие
- Легко тестировать и отлаживать

Микросервисы имели бы смысл, если бы разные команды отвечали за разные части или требовалось бы разное масштабирование компонентов.

### Брокер сообщений

В production-среде с высокой нагрузкой можно добавить RabbitMQ:
- Запросы ставятся в очередь, обрабатываются асинхронно
- Можно накапливать батчи для пакетной обработки
- Отдельный сервис пишет логи в Elasticsearch

### Логирование

Текущая реализация пишет логи в stdout в формате JSON. В реальной системе они собираются через Fluentd → Elasticsearch → Kibana.

Пример лога:
```json
{"timestamp": "2026-05-03T12:00:00Z", "endpoint": "/predict", "accuracy": true, "latency_ms": 45}
```

## ONNX и оптимизация

Для ускорения инференса модель можно преобразовать в формат ONNX:

```python
from skl2onnx import convert_sklearn
from skl2onnx.common.data_types import FloatTensorType

initial_type = [('float_input', FloatTensorType([None, 23]))]
onnx_model = convert_sklearn(model, initial_types=initial_type)

with open("model.onnx", "wb") as f:
    f.write(onnx_model.SerializeToString())
```

Это позволяет использовать ONNX Runtime -специализированный движок для быстрого выполнения моделей.

## uWSGI и NGINX в production

Flask -сервер разработки, не предназначен для высокой нагрузки. В production используется связка:

- **uWSGI** -запускает несколько воркеров (процессов), обрабатывают запросы параллельно
- **NGINX** -обратный прокси, раздает статику, балансирует нагрузку, защищает от DDoS

Схема: `Клиент → NGINX:80 → uWSGI → Flask App`

## A/B тестирование


Модели v1 и v2 показывают похожую точность, но на разных типах клиентов могут работать по-разному. A/B тест позволяет проверить, какая модель лучше на реальном трафике.

### Постановка

| Параметр | Значение |
|----------|----------|
| Контрольная группа | v1 (RandomForest) |
| Тестовая группа | v2 (GradientBoosting) |
| Сплит | 50/50 по user_id |
| Продолжительность | минимум 14 дней |
| Целевой объем | 1000+ предсказаний на группу |

### Метрики

**Основная:** F1-score для класса дефолта
- Баланс между Precision и Recall
- Важно не пропустить дефолтников, но и не отклонить хороших клиентов

**Дополнительная:** Precision
- Цена ложного положительного срабатывания высока -отказ добросовестному клиенту = прямые убытки

### Статистический анализ

Используется двухвыборочный z-тест для долей.

Доверительный интервал 95%:
```
(p_test - p_control) ± 1.96 × SE
```

Критерий успеха:
- p-value < 0.05 И прирост F1 > 0.02 → внедряем v2
- p-value >= 0.05 → продолжаем собирать данные
- p-value < 0.05 И F1 снизился, оставляем v1

### Бизнес-метрики

Помимо технических метрик, для банка важны:

1. Снижение убытков от дефолтов - сколько клиентов с высокой вероятностью дефолта правильно выявлены
2. Доля одобренных заявок при том же уровне риска - сколько хороших клиентов получили кредит без увеличения риска
